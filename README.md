# Zpi

Zpi is an experimental Zig terminal coding agent inspired by [pi](https://github.com/earendil-works/pi) and [pi-rust](https://github.com/bigfish1913/pi-rust). Its current slice supports OpenAI Chat Completions, an OpenAI Responses (`openai-responses`) text/tool subset, and an Anthropic Messages text/tool subset, streamed text and tool calls, `read`/`write`/`edit`/`bash`/`grep`/`find`/`ls`, persistent Zpi JSONL sessions, a regular terminal interface, print mode and Zpi JSONL event output. It is **not yet production-ready** or broadly compatible with pi.

## Build and use

Requires Zig **0.17.0** on macOS or Linux. The CLI links dynamically to the target system C library for native plugin loading; Linux musl builds require the matching musl loader, and glibc builds require glibc. `grep` requires `rg` on PATH; `find` requires `fd` or `fdfind`. These dependencies are installed separately; Zpi does not download tool binaries. `ls` runs directly in Zig. `edit` accepts either a single `oldText`/`newText` pair or `edits[]`, matching all replacements against the original file and rejecting overlap or ambiguity.

Build and run:

```sh
zig build
./zig-out/bin/zpi --help
export OPENAI_API_KEY=...    # or use a configured compatible provider
./zig-out/bin/zpi -p "Explain this project"
./zig-out/bin/zpi             # interactive terminal
```

A compatible endpoint and exact model can be selected with `--endpoint`, `--model`, `--provider`, and `--thinking` (`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, or a `:level` suffix on `--model` when it does not match a literal model ID). Configuration defaults to `~/.zpi/agent/models.json` and `~/.zpi/agent/settings.json`; the pi-compatible `PI_CODING_AGENT_DIR` selects the agent config directory, followed by `ZPI_MODELS_FILE` and `--models-file` for models. `settings.json` supports `defaultProvider`, `defaultModel`, `defaultThinkingLevel`, `modelThinkingLevels`, `defaultTools`, `compaction` (including `modelOverrides`), `retry`, `sessionDir`, `hideThinkingBlock`, and `quietStartup`. In interactive mode, `/model [ref]` lists or switches models mid-session and `/thinking [level]` adjusts reasoning effort without restarting. A compatible provider in the existing pi configuration can be selected explicitly:

```sh
./zig-out/bin/zpi --models-file "$HOME/.pi/agent/models.json" \
  --provider amd-radeon --model MiniCPM5-2B --no-proxy --no-tools \
  -p "Reply briefly with READY"
```

`--no-proxy` deliberately bypasses system proxy variables (`http_proxy`, `https_proxy`, `all_proxy`) and connects directly. Without `--no-proxy`, Zpi honors `NO_PROXY`/`no_proxy` bypass rules (wildcards, host/domain suffixes, IPv6 literals, and optional ports) and tunnels HTTPS requests through `https_proxy`/`all_proxy` via HTTP `CONNECT` (including `Proxy-Authorization` Basic credentials and TLS-in-TLS for `https://` proxies) before negotiating verified origin TLS (`SSL_CERT_FILE` or OS root certificates). `--no-tools` is useful for simple conversations. Adapters support `openai-completions`, `openai-responses`, and `anthropic-messages`, selected by provider or model `api` in `models.json`. `openai-responses` posts `"store": false` and `max_output_tokens` (enforcing a 16-token floor) to `/responses`, encodes `system`/`user` (`input_text`), `assistant` (`output_text` + `function_call`), and `tool_result` (`function_call_output` splitting `call_id|fc_id`), streams thinking/text/function-call SSE events, and validates all tool calls before dispatch. Images, `reasoning.encrypted_content` replay, grammar/custom tools, and Azure/Responses compat flags remain unsupported on `openai-responses`. The supported configuration subset includes `baseUrl`, `apiKey` as a literal or environment variable, model IDs, and bounded provider/model `headers`. Provider headers are the base layer, followed by `modelOverrides[modelId].headers` and then model-definition headers. Later layers replace matching names case-insensitively, matching pi 1.5.2's models.json precedence; the provider-auth merge is a narrower subset, and Zpi normalizes case to avoid duplicate wire headers. Values accept literal text, `$VAR`/`${VAR}` references and pi-style `$$`/`$!` escapes; unresolved variables and shell-command references are rejected. Framing and connection headers, duplicates, malformed names/values, and sets over 64 headers or 16 KiB are rejected before a request. `authorization`, `accept`, `x-api-key` and `anthropic-version` may be overridden, so configured headers can replace the default credentials. `--provider anthropic` also reads `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` and `ANTHROPIC_BASE_URL` (default `https://api.anthropic.com/v1`). Anthropic sends `x-api-key` and the version header, groups tool results, and validates all calls before execution. Thinking/signature replay, images, OAuth and command-valued credentials are explicitly unsupported; malformed tool JSON is rejected rather than repaired. OpenAI models can set `compat.maxTokensField` (`max_tokens` or `max_completion_tokens`), `compat.requiresNonNullAssistantContent`, `compat.requiresToolsWithToolHistory`, `compat.requiresToolResultName`, and `compat.requiresAssistantAfterToolResult`. With `compat.supportsUsageInStreaming` enabled (the default), Zpi requests `stream_options.include_usage`. With `compat.supportsFinishReason` enabled (the default), Zpi requires a recognized terminal `finish_reason`. Enable `compat.supportsStore` to send `"store": false`. Zpi omits the field by default. When `supportsFinishReason` is explicitly disabled, Zpi infers `stop` or `tool_use` at `[DONE]` from whether the response contains tool calls. The `[DONE]` marker is required; premature EOF remains a truncated response. Zpi applies these settings in order from the provider, the selected model, and its `modelOverrides` entry. The last value for each setting wins. `requiresNonNullAssistantContent` sends `""` for assistant messages that contain tool calls but no text. `requiresToolsWithToolHistory` sends `"tools": []` when the conversation contains prior tool calls or results and the current tool selection is empty. `requiresToolResultName` includes the recorded tool name in tool-result messages when available. `requiresAssistantAfterToolResult` inserts pi's assistant bridge when a user message immediately follows a tool result. Zpi rejects invalid types for these settings. Automatic compatibility detection and nested routing options remain pending.

The selected `models.json` accepts a leading UTF-8 BOM, `//` line comments and trailing commas in objects/arrays, following the pinned pi loader's syntax subset. Strings retain comment-like text and escapes. Files must be UTF-8 and stay within 4 MiB; block comments remain unsupported. Invalid syntax is rejected before session creation or plugin loading.

Without `--provider`, `--model PROVIDER/ID` recognizes `openai`, `anthropic`, and provider keys in the selected models.json. Provider prefixes match case-insensitively, with the longest known prefix winning. On that provider, the exact ID after the prefix takes priority; if it is absent, an exact match for the full argument is used, preserving IDs such as `openrouter/free`. The remaining model ID retains its spelling, slashes and colons. Unknown prefixes remain part of the literal model ID on the default OpenAI provider. With an explicit `--provider`, the entire `--model` value is literal, and omitting `--model` retains the existing provider default selection. A recognized prefix with an empty model ID is rejected. A reference that also names a configured literal model ID on a different provider is rejected as ambiguous; use `--provider` to choose explicitly. Known built-in provider names are always recognized as prefixes, even without a models.json entry. This bounded routing subset does not implement pi's catalog-wide matching, credential-based tie breaking, fuzzy names or thinking suffixes.

Model entries may set `maxTokens`; an exact `modelOverrides[modelId].maxTokens` replaces that value. The default output limit is 16,384. Anthropic sends it as `max_tokens`; OpenAI defaults to `max_tokens` and honors the documented compat override for `max_completion_tokens`. Positive `contextWindow` values are recognized on model entries and model overrides; the latter wins, and the configured window is passed through the provider selected by `--model PROVIDER/ID`. As in pi, a matched custom model definition defaults to a 128,000-token context window when omitted; an explicit model override may replace it. When a context window is available, Zpi estimates input from UTF-16 code-unit lengths at 3.5 units/token, matching JavaScript string lengths for valid Unicode, plus tool schemas and an approximate image allowance, then applies pi's 4,096-token fixed margin and 15% ratio margin. When the ratio margin leaves fewer than 32,768 output tokens, it uses the fixed margin with a 32,768-token fallback cap. The configured `maxTokens` remains the ceiling, with a one-token floor even when the estimated context is already full. When no matching custom model definition supplies a window, clipping is disabled. Each request is recalculated against the projected active history, including after session reload. This is an approximate subset: provider-usage prefix anchors are not implemented, tokenizer equivalence is absent, serialized tool schemas may differ from pi's representation, image accounting is coarse, and context estimation does not enable image or thinking replay. Malformed UTF-8 in estimated content is rejected. Zpi accepts positive JSON integer literals up to 4,294,967,295 for these fields (decimal-point and exponent spellings are rejected), and rejects invalid values before session creation or plugin loading. Provider-level limits and model-catalog discovery remain unsupported.

`read` preserves selected text newlines and applies 2,000-line or 50 KiB complete-line caps. Truncated results include a continuation offset and structured truncation details; explicit line limits report remaining lines. A zero limit selects no lines and reports the continuation offset. Offsets must be positive integers; limits must be nonnegative integers. Text file reads share an inclusive 8 MiB boundary with `write` and `edit`. Image and streaming reads remain unsupported.

`edit` accepts either a single `oldText`/`newText` pair or `edits[]`, matching all replacements against the original file, rejecting overlap or ambiguity, and returning a numbered hunk `diff` plus `firstChangedLine` in tool `details` (rendered as a colored preview in interactive mode).

`bash` combines stdout and stderr, displays `(no output)` when both are empty, and appends an exit code when a command fails. Signal termination uses the shell convention `128 + signal`. Commands currently run through `/bin/sh`, with a 60-second default timeout (maximum 3,600 seconds), tail truncation to the last 2,000 lines or 50 KiB (whichever is hit first, spilling the full output up to 32 MiB to a `0600` temp file in `$TMPDIR` or `/tmp`), and process-group termination on timeout, cancellation, or spill overflow.

By default, non-TTY stdin or stdout selects print mode. Piped stdin is read as UTF-8, trimmed and limited to 1 MiB. Explicit `@file` text arguments are wrapped with their absolute launch-directory path and prepended, in order, to the positional prompt; each file is limited to 1 MiB and the combined initial prompt to 4 MiB. Empty files are skipped; BOMs are stripped; binary/image inputs are rejected. `~` and Unicode spaces in paths are normalized. An empty initial prompt is rejected before sessions, configuration or plugins are opened. `--mode text` selects interactive mode on a terminal and print mode when redirected, like pi. Explicit `--print` remains compatible with `--mode text`. Image attachments and pi's screenshot-name fallback are not implemented.

`--system-prompt TEXT_OR_PATH` replaces the system instructions; repeat `--append-system-prompt TEXT_OR_PATH` to append sections in order. An existing file is read as UTF-8 with its BOM removed; otherwise the argument is literal text. Paths resolve from the launch directory and support `~/` expansion using `HOME`. Invalid files are rejected, and the composed system prompt is limited to 1 MiB. Changes are stored as full Zpi system checkpoints, so reopening or selecting an earlier branch restores that branch's instructions. Appending on resume extends the saved instructions. This persistence behavior is a Zpi subset; pi's section patches and automatic `SYSTEM.md`/`APPEND_SYSTEM.md` discovery are not implemented.

Agent Skills are a partial subset. Zpi discovers user skills under `$PI_CODING_AGENT_DIR/skills` (or `~/.zpi/agent/skills`), advertises bounded `SKILL.md` frontmatter in the system prompt, and expands `/skill:name args` into that skill's body plus the supplied request. A relative `PI_CODING_AGENT_DIR` resolves from the launch directory. Pass `--skill PATH` to add a skill directory or `SKILL.md` file. Relative `--skill` paths resolve from the effective project directory, including when you use `--cwd`. Project skills under `.agents/skills` and `.zpi/agent/skills` require `--trust-project-skills`. `--no-skills` disables discovery and explicit skill paths for the current invocation. Sessions keep previous expanded Skill messages as conversation history. The Skills index is rebuilt on each invocation. Discovery and file sizes are bounded. Frontmatter uses a scalar parser, not YAML. Full Agent Skills validation, `/reload`, settings and package resources are unsupported. Project skill trust is an explicit Zpi boundary; review instructions before enabling them.

Prompt templates turn Markdown files into reusable `/commands`. For example, put `Review the changes for ${1:-correctness}.` in `~/.zpi/agent/prompts/review.md`, then run `zpi -p '/review "API compatibility"'`. User templates are read directly from `$PI_CODING_AGENT_DIR/prompts` or `~/.zpi/agent/prompts`. A relative `PI_CODING_AGENT_DIR` resolves from the launch directory. `.zpi/prompts` in the effective project directory requires `--trust-project-prompts`. Repeat `--prompt-template PATH` to add a file or directory, with relative paths resolved from the effective project directory. For duplicate names, the first valid template wins in user, trusted project, then explicit path order. `--no-prompt-templates` (or `-np`) disables default discovery but keeps explicit paths.

Expansion supports quoted arguments, `$1`, `$2`, `$@`, `$ARGUMENTS`, defaults such as `${1:-correctness}`, and slices such as `${@:2:3}`. Zpi strips delimited frontmatter without parsing or using its metadata. Expansion happens after extension input transforms and skill expansion; only the resulting user text is saved in the session. Template files are limited to 256 KiB and expanded text to 1 MiB. Templates do not execute code. The interactive terminal handles `/help`, `/session`, `/hotkeys`, `/model [ref]`, `/thinking [level]`, `/compact [focus]`, `/exit` and `/quit` as built-ins when entered without conflicting template expansions, and supports Zig-native raw-mode line editing (UTF-8 cursor movement, in-session history, multi-line bracketed paste / `Alt+Enter`, `Tab` completion for built-in `/commands`, discovered `/skill:...` and template commands, and `@paths`, plus queued follow-up editing while a turn is running: `Enter` queues the next message, `Alt+Up` restores queued messages into the editor, `Esc` clears the active draft, and `Ctrl-C` cancels the active turn while preserving queued text in the prompt). Those built-in names can still be used as templates in print mode. `/reload`, packages and settings-based discovery remain unsupported.

Long conversations can be summarized manually with `/compact [optional focus]` in interactive mode, and automatically when an active `contextWindow` exceeds `contextWindow - 16384` tokens (or once on a `413` / empty-length overflow). Compaction preserves intact tool-call/result batches, records a lossless `compaction` entry in the Zpi JSONL tree (keeping pre-compaction history branchable via `--branch ENTRY-ID`), and projects the latest system prompt checkpoint plus the structured summary and kept recent messages on resume. Transient provider failures (`429`, `500`/`502`/`503`/`504`/`520`-`529`, stream drops, and request timeouts before any streamed output arrives) automatically retry up to 3 times with exponential backoff (respecting `Retry-After` / `Retry-After-Ms` up to 60s) and cancel immediately on `Ctrl-C`.

Default built-in tools are `read`, `bash`, `edit` and `write`. Select others with `--tools read,grep,find,ls` or add them with `--tools +grep,+find,+ls`. A plain list replaces the selection and accepts `*` patterns; a list of exact `+name`/`-name` entries changes the defaults in order. `--exclude-tools 'pattern*'` applies last. `--no-builtin-tools` keeps plugin tools; `--no-tools` disables all tools by default, and an explicit selection can enable them again. Selection applies to both model declarations and dispatch, including native and TypeScript tools. Explicitly selected plugins still load with these flags. Settings-based defaults and dynamic exposure remain unsupported.

Opt-in experimental stdio MCP servers can be started with repeatable `--mcp-stdio NAME -- EXECUTABLE ARG...` declarations. Put Zpi options and any positional prompt before the server declarations, for example `zpi -p "task" --mcp-stdio docs -- docs-server`. Each declaration consumes the child arguments up to the next `--mcp-stdio` or the end of the command line. Each server name must be unique after case folding and `-`/`_` normalization; the protocol's reported server name is ignored. Tools use `mcp__NAME__TOOL` with non-alphanumeric characters mapped to `_`, and are subject to the same `--tools`/`--no-tools` selection and dispatch. Only text results up to 50 KiB are supported. A tool result marked `isError` is returned to the model and persists when sessions are enabled. A lost reply or JSON-RPC error after dispatch stops the turn without automatic retry and records an unknown outcome when sessions are enabled. Servers start before extension loading, inherit the process environment, and run with the same OS permissions as Zpi. Use only trusted server commands; `--no-tools` filters dispatch but does not prevent explicitly selected servers from starting. HTTP, `mcp.json` discovery, credentials, resources, progress, pagination and reload are not implemented.

An experimental native plugin runtime is available separately from the TypeScript host. Build plugins for the same OS, architecture, and C ABI, then opt in by absolute path: `./zig-out/bin/zpi --native-plugin /absolute/path/to/plugin.dylib -p "Use the native tool"`. Repeat the option to load multiple plugins. Native tool calls, progress, error results, JSON `tool_execution_update` events, and session persistence are integrated into the agent loop. `--no-tools` loads explicitly chosen modules and leaves tools disabled unless `--tools` enables them explicitly. Plugins run in-process with full process privileges; this is not a sandbox. The C contract and loader are experimental, have no Rust fixture yet, and do not imply a stable ABI. See [native ABI status](docs/spec/native-plugin-abi.md) and the [runtime contract](docs/spec/native-plugin-runtime.md).

Sessions are created under `~/.zpi/agent/sessions/`; pass `--session PATH` to create or resume a specific session, or `--no-session` for in-memory history. `--continue` (or `-c`) opens the most recently modified session whose recorded working directory matches the current directory or `--cwd`; it creates a session when none match. Discovery scans at most 10,000 directory entries and reads at most 64 KiB per header. Equal modification times use lexical path order. `--continue` and `--session` cannot be combined. Symlink files and invalid headers are ignored; a selected conversation that is corrupt, oversized or locked returns an error without falling back to an older session. Working directories are compared after lexical normalization; symlink aliases are distinct. `--session-dir PATH` selects the directory for new sessions and `--continue`; `PI_CODING_AGENT_SESSION_DIR` provides the same setting when the CLI option is absent. Both expand `~/`; relative paths resolve from the launch directory, and an explicit directory works without `HOME`. An explicit `--session PATH` takes precedence. Pi's session picker and session ID lookup remain pending. `settings.json` can set a default `sessionDir`. To continue after an earlier entry, use `--session PATH --branch ENTRY-ID -p "Explore another approach"`. Entry IDs are in the session's message records. This appends an active-leaf record and retains the abandoned branch; later prompts use only the selected ancestry. The session must already exist and the entry ID must match exactly. The regular interactive terminal also provides `/session`, `/compact [focus]`, and `/hotkeys`. Zpi uses its own JSONL session and event formats. Ordinary session records, `compaction`, and `branch_summary` use version 1. Full system-prompt checkpoints use version 2. Use a current Zpi binary to reopen sessions that contain `branch_summary` records. An incomplete final record is discarded on resume; complete malformed records stop loading. Failed requests are persisted. If a request ends after recording a tool call but before its result, Zpi adds an explicit “outcome unknown” error result when reopening and does not replay the effect. Inspect affected files or processes before retrying. Model/tool contents can appear in session files. Commands can read, modify and execute with the operating-system permissions of the user running Zpi. The working directory is a default path, not a sandbox. Native plugin registration, execution, progress, cancellation, and session result details are integrated experimentally; Rust interoperability, a frozen ABI, full MCP parity, full prompt-template compatibility and pi package support remain future work. TypeScript extensions have an experimental opt-in subset described below.

### Navigate within a session

- `/tree` opens a keyboard picker with message previews and indented entries in session order. `*` marks the active entry and `>` marks the cursor. Move with Up/Down, Page Up/Page Down, or Home/End. Enter switches locally. Esc or Ctrl-C returns to the prompt without switching. The picker shows up to 20 entries at once. The picker follows terminal resize and preserves regular scrollback.
- `/tree --list` prints the 50 most recent entries with their IDs and parent IDs. `/tree --older ENTRY-ID` prints the preceding page. With `TERM=dumb`, bare `/tree` prints the list.
- `/tree ENTRY-ID` switches directly without a model request. Both picker and direct navigation reject entries with incomplete tool batches. Switching preserves both branches and leaves filesystem changes in place.
- Press `s` in the picker to request a branch summary. Zpi displays a separate confirmation before sending the departed conversation to the active provider: press `y` to continue, or `n` to return to the picker. If the terminal is too small to display the confirmation, summary generation is unavailable until it is resized.
- `/tree --summary ENTRY-ID` explicitly sends the departed conversation after the common ancestor to the active provider. The request omits system messages and tool results, retains assistant tool-call descriptions, and exposes no tools. Zpi appends the summary after the selected entry and restores it on reopen. If generation fails or is canceled before the switch commits, the active branch stays where it was.

Pi's prompt prefill, tree filtering, and labels remain pending.

## Import a pi v3 session

```sh
./zig-out/bin/zpi --import-pi-session ./pi-session.jsonl --session ./zpi-session.jsonl
./zig-out/bin/zpi --session ./zpi-session.jsonl --no-tools -p "Summarize where we left off"
```

Import is an offline conversion. It leaves the source untouched and creates a private Zpi file in an existing directory. The destination must be new. Use a closed pi session or a stable copy. Zpi follows the parent chain of the last entry and copies that branch's text, optional leading system prompt, and completed tool-call/result batches. Historical calls are never executed. The converted session uses the source working directory unless you pass `--cwd` when resuming. Your Zpi configuration and resume flags determine the provider and enabled tools.

Text from extension `custom_message` entries and messages with the `custom` role becomes user-role history. This includes messages hidden from pi’s terminal display. Nonempty `branch_summary` entries also become user-role history using pi's summary wrapper. Empty summaries are skipped. Import discards extension display metadata, summary metadata, state-only `custom` entries, inactive branches, labels, accounting, and pi model and tool configuration. The latest edit to each supported message on the active branch replaces its content or omits it. A later replacement can restore a message omitted by an earlier edit. The resulting history must retain complete tool-call/result batches.

For compacted sessions, import uses the latest compaction on the active branch. It writes the optional system checkpoint and the summary before the retained conversation, then includes messages after the compaction. Edits apply to the retained context. An invalid retention boundary or a retained tool batch with a missing call or result fails before publication.

Import rejects later system updates, images, and thinking blocks in the projected conversation. It accepts UTF-8 sources up to 32 MiB, with up to 100,000 entries, 8 MiB per record, and a JSON nesting limit of 64. Review imported instructions before resuming with tools enabled.

## Existing pi TypeScript extensions

With Node and a user-installed `@earendil-works/pi-coding-agent` (**1.5.2** or **1.6.0**), select trusted extensions explicitly:

```sh
./zig-out/bin/zpi --pi-sdk /absolute/path/to/@earendil-works/pi-coding-agent \
  -e /absolute/path/to/extension.ts -p "Use the extension tool"
```

This uses pi's actual loader, SDK imports and runner in a Node child. Input transforms, text tools, tool-call gates/mutations, result hooks and persisted result `details` have offline fixtures. When `ZPI_PI_SDK` points to pi 1.5.2 or 1.6.0, the CLI suite also compares an imported pi v3 text/tool transcript against that SDK's active-context projection. Extensions receive print-mode context (`hasUI: false`) in every Zpi mode. Session/model registry APIs, TUI, commands, dynamic registration, reload and nested tools remain unsupported. Interactive `Ctrl-C` cancels in-flight turns and child-process tools and reconciles interrupted batches without replay; the Node host deadline or cancellation terminates an uncooperative host process group. Explicit paths authorize loading executable code with your OS permissions; no project auto-discovery or package installation occurs. See the [tested extension subset](docs/spec/typescript-extension-host.md) for version, protocol and ownership limits.

## Verify

```sh
zig build test
zig build
zig fmt --check build.zig src/*.zig src/cli/*.zig
python3 scripts/test-cli.py
python3 scripts/test-package-release.py
sh scripts/test-linux-containers.sh
```

The repository CI also runs the pinned Zig suite, offline CLI, native plugin fixtures, ReleaseSafe archive smoke and pi 1.6.0 extension fixtures on Linux x64 and macOS arm64/x64. See [platform verification](docs/spec/platform-verification.md) for local guest evidence and cases CI cannot establish.

The offline integration test uses an isolated temporary workspace and local fake provider; it checks file and shell tools, search tools when their dependencies are installed, session resume and branching, system-prompt replace/append/reload, tool selection, piped stdin and `@file` text inputs, print/JSONL output and a terminal PTY. Set `ZPI_TEST_NATIVE_PLUGINS` to a path-list of built native fixtures to include plugin invoke/progress/session/`--no-tools` CLI coverage. The musl script cross-builds on macOS and runs the artifacts in Apple Container and Colima on arm64 and translated amd64. Run `sh scripts/test-linux-glibc.sh` to cross-build `aarch64-linux-gnu.2.39` and run the artifacts in Colima's Linux VM. Run `sh scripts/test-linux-native-glibc.sh /absolute/path/to/zig-aarch64-linux-0.17.0.tar.xz` to compile in the arm64 Ubuntu guest with its native Zig toolchain. The glibc runs report any search tests skipped due to missing `rg` or `fd`/`fdfind`. The scripts may start the local virtualization services and leave them running. See [platform verification](docs/spec/platform-verification.md) for exact coverage and limits.

zig build provider-smoke -- MiniCPM5-2B
