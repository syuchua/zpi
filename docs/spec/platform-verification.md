# Platform verification

The local host is macOS arm64 with Zig 0.17.0. Apple Container 1.6.1 and Colima 0.10.3 provide Linux execution. Both services were started for project tests. Colima startup selected the `colima` Docker context; test scripts use `docker --context colima` explicitly.

## Reproduce

```sh
zig build test
zig build
zig fmt --check build.zig build.zig.zon src
python3 scripts/test-cli.py
sh scripts/test-linux-containers.sh
sh scripts/test-linux-glibc.sh
sh scripts/test-linux-native.sh
# Native arm64 Ubuntu/glibc build (requires the verified aarch64 Linux Zig archive):
sh scripts/test-linux-native-glibc.sh /absolute/path/to/zig-aarch64-linux-0.17.0.tar.xz
```

`scripts/test-linux-containers.sh` cross-compiles the CLI and test executables on macOS, then executes them inside Linux. It builds a test image in Colima with `rg`, `fd` and Python, exports it, and loads the same image into Apple Container. Guest mounts expose the built artifacts read-only. The base is `alpine:3.24.3` (OCI index digest `sha256:be2656061b536c1883c4034790e21d0a09c5aaaf51968b89368a3c0371ea2c9a`). `ZPI_TEST_IMAGE` selects the image prefix; `ZPI_BUILD_TEST_IMAGE=0` reuses its existing `-arm64` and `-amd64` tags. Set `ZPI_TEST_BUILD_PROXY` when the Colima build needs a guest-reachable package proxy. Services remain running; test containers use `--rm`.

The reusable `scripts/test-linux-artifacts.sh` runs every installed test binary, dynamic C/Zig plugin fixture, help/version check, offline CLI fixture and context-budget integration. It requires `rg` and `fd` or `fdfind` by default; `--allow-search-skips` explicitly permits a reduced-coverage run. `scripts/test-linux-glibc.sh` cross-builds `aarch64-linux-gnu.2.39` artifacts with Zig 0.17.0, stages them in Colima's Ubuntu 24.04 arm64 Linux VM, and executes the reusable runner there. The VM does not currently have `rg`/`fd`, so the script opts into those skips; this is glibc runtime evidence, not complete search coverage, native Linux compilation or native amd64 evidence. Regression `b33bf6ec7` exited 0: the installed suite recorded **129 passes, five skips and zero failures** (two search, three SDK-dependent), plus native C/Zig fixtures, CLI integration and 56 context-budget checks. Fixture hashes matched the working copies. The earlier exploratory Colima VM run `b86e72de9` had the same counts. An Ubuntu test image build (`bdc223cce`) stopped while fetching the base image from the Docker mirror. The glibc script now uses the existing Colima VM. Logs are in `.pi/tasks/01a1d9a6-2322-729e-9a34-0a4df7c3b930-85015/b33bf6ec7.output` and `b86e72de9.output`.

`scripts/test-linux-native.sh` builds and runs the suite inside an arm64 Alpine 3.24.3 guest in Colima. It verifies the official Zig 0.17.0 `zig-aarch64-linux` archive against SHA-256 `9e8d11661d4ae3bd57702a3832781e23ad151dde5798e16a5ccd503f65234ff8`. Set `ZPI_LINUX_ZIG_STAGE` to reuse an archive named `zig.tar.xz` from a different directory. The script stages the project sources read-only, copies them to the guest workspace, and builds with guest-local caches and outputs. The image build can fetch packages and the runner starts the test guest with networking disabled. The guest runs `zig build install test-binaries --summary all`, followed by `scripts/test-linux-artifacts.sh` against that install prefix.

`scripts/test-linux-native-glibc.sh` takes an absolute path to the same verified arm64 Zig archive. It extracts the archive on macOS and stages the compiler and project sources in a temporary workspace in the Ubuntu 24.04 arm64 Colima VM. The VM runs `zig build install test-binaries -j2 --summary all` using the Linux Zig executable and a guest-local cache, reports the glibc version and dynamic linkage, and runs the artifact suite with `--allow-search-skips`. The runner removes its temporary workspaces on exit. The earlier `b25b8c23f` attempt verified the toolchain archive but stopped before compilation because the Ubuntu guest lacked `xz`. Host-side extraction removes that dependency.

## Further acceptance

- Extend the same build-installed test executables as real core behavior lands; preserve failures and distinguish compilation from execution.
- Verify builds with a pinned Zig toolchain running on Linux. Use native x86_64 CI for release verification and performance measurements.
- Keep running the provider parsing/localhost HTTP/SSE, session recovery and filesystem/shell timeout suites in Linux; add dynamic-library interoperability fixtures as that implementation lands.
- C/Zig layout, value ownership, shared-library loading and fake-provider CLI workflows execute on macOS and cross-built Linux guests. Add Rust fixture tooling before claiming Rust interoperability.
- Exercise TUI through a PTY plus manual native terminal runs: resize, Unicode/IME placement, paste, Ctrl-C, exit cleanup and redirected streams. A non-TTY container smoke test cannot prove terminal behavior.
- Collect cold-start, memory and plugin-call measurements using release builds; record virtualization/emulation rather than comparing them to native benchmarks.
