# Zpi v0.1.3

This release adds opt-in capability authorization and JSONL auditing to Zpi. It also improves setup diagnostics and project context handling.

## Highlights

- **Capability authorization and audit.** Enable secure mode with `--security secure` and `--audit-log PATH`. Grant individual capabilities for a single check, a session, or an invocation, or load an explicit persistent policy. The redacted audit records link authorization decisions to observed outcomes. Compatibility mode remains the default.
- **Offline diagnostics.** `zpi doctor` checks local setup, and `--verbose` provides static hints for capability, policy-file, and audit-log errors. Unknown long options report `UnknownOption`.
- **Opt-in project context.** Load `AGENTS.md` and `CLAUDE.md` as project data with `--enable-project-context` or the project-local setting. `--no-context-files` overrides either opt-in.
- **Version and builds.** MCP `clientInfo.version` and `zpi --version` use the same package version. Plain `zig build` defaults to ReleaseSafe. Explicit Debug builds and `-Dtui=none` remain available.

See the [security notes](../security.md) for a secure-mode example and the [installation guide](../install.md) for platform archives and checksum verification.
